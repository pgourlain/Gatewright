# ADR 0015: Move to .NET 11, keep .NET 10 LTS for the published libraries

- Status: Accepted
- Date: 2026-11-12

## Context

CLAUDE.md §3 fixed the stack on .NET 10 (LTS). .NET 11 was released in November 2026, and
Dependabot opened #11 (`dotnet/aspnet` 10.0 → 11.0) and #12 (`dotnet/sdk` 10.0 → 11.0). #11 broke
the Kubernetes e2e run: the image ran the .NET 11 runtime while the application was built for
`net10.0`, which a runtime image of a newer major does not run. A runtime major change has to be a
decision, not a dependency bump.

.NET 11 is an STS release. Under the support policy in force since 2025 (24 months for STS), its
end of support lines up with .NET 10 LTS, so moving does not shorten our support window.

Two kinds of artifacts are affected differently:

- **Applications** we ship as images or tools: `Gatewright.Host`, `Gatewright.Portal`, the
  `gatewright` CLI, the `dotnet new gatewright-host` template. We choose their runtime.
- **NuGet libraries** customers compile against (distribution model, D9): `Gatewright.Abstractions`,
  `Gatewright.Sdk`, `Gatewright.Exposure`, `Gatewright.Testing`, and the internal projects `Sdk`
  references (Core, DataPlane, ControlPlane, Distribution, Kubernetes, Policies, State.Redis).
  A customer on .NET 10 LTS must not be forced to move.

## Decision

1. Applications, tests and samples target `net11.0`. The template generates a `net11.0` host.
2. Every library under `src/` (all projects except Host, Portal and Cli) multi-targets
   `net10.0;net11.0`. This is set once in `Directory.Build.props`.
3. Framework-aligned packages (`Microsoft.AspNetCore.*`, `Microsoft.Extensions.Options`/`DI`) get
   per-target versions in `Directory.Packages.props`: 10.0.x for `net10.0`, 11.0.x for `net11.0`.
   ASP.NET Core 11 packages target `net11.0` only.
4. The EF Core stack stays on 10.x for both targets. `Npgsql.EntityFrameworkCore.PostgreSQL` 11
   is still a release candidate, and 10.x pins EF Core below 11. EF Core 10 runs on .NET 11. We
   revisit this when Npgsql 11 is released.
5. The official images move to the .NET 11 chiseled base. For .NET 11 this is Ubuntu 26.04
   (`resolute-chiseled`); no `noble` variant exists.
6. The OpenAPI importer accepts OpenAPI 3.2, the default version ASP.NET Core 11 generates.

## Consequences

- No breaking change for customers: a .NET 10 distribution keeps building against the same
  packages and resolves the `net10.0` assets.
- CI builds both targets of every library. Tests run on `net11.0` only, so the `net10.0` builds are
  checked by compilation, not by tests.
- The next runtime major (12) goes through a new ADR. Dependabot ignores major versions of the
  `dotnet/*` images.
- SDK 11 brings new analyzers (CA2026 `JsonElement.Parse`, Blazor BL0013), and the code was fixed
  to satisfy them. No rule was disabled.
